## Authoritative conclusion

The publishing scheduler process is running but locked into non-executing policy. The dedicated readiness worker is genuinely active and performs external Telegram probes plus database updates. Production systemd correctly disables the web readiness duplicate, but the committed deployment unit omits that override. The AI auto loop is enabled in a live systemd drop-in while its configured Telegram gateway is inactive. Telegram gateway, bot, and Kathleen listener are not running, although Kathleen’s configuration says enabled.

Verdict: `ZOLLOTEX_PHASE0_5_SCHEDULER_TRUTH_PASS` for observation/reconciliation only. Runtime cleanup is not authorized in this phase and remains a deployment blocker.
