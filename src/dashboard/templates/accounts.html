Use an account for Scheduler (send messages to groups): In the Purpose column below, set the account to Messaging or Both. Then it will appear in Scheduler when you choose "Select user".
Operator console — two different checks:
  • General health (sync or fleet): Can this session talk to Telegram? Outcomes like alive, frozen, auth_required refer to this layer only.
  • Story readiness (precheck / safety policy): May the account post stories right now? An account can be alive but still need story precheck (never run or expired). That is expected — use the story precheck card below when ready.

Suggested order: Run general health first (sync selected rows or fleet), then use Story readiness — controlled precheck when the table shows Story: precheck. In the table Publish column: YES/NO plus short Reason/Action; open Details for full policy text, diagnostics, and raw precheck errors.

Story readiness — controlled precheck

This uses the story layer only (Telegram CanSendStoryRequest), not general account health. Does not publish stories — no media is uploaded; it only asks Telegram whether story posting would be allowed right now. Candidates are accounts that: status active, have a canonical session file, and show needs_precheck in story readiness (never run or TTL expired). Server rules still apply: hourly cap, and multi-account batches require explicit confirmation (canary_batch_ok) in line with backend safeguards.

Publish-ready: what is included / excluded
  • Included — Same snapshot as Eligible (active, alive, session, fresh story precheck for publish TTL, warmup/cooldown/caps clear per policy) and purpose is Stories only or Both.
  • Excluded vs Eligible — Messaging-only accounts (scheduler) never appear in Publish-ready.
  • Excluded from Eligible entirely — Manual (manual_review_required), precheck needed/stale, frozen/restricted/rate-limited story layer, and other policy blocks (see Publish Reason / Details).
  • Not a publish command — This page prepares lists only; actual publish paths still run safety checks.

Add New Account
Code goes to Telegram app ("Login code: XXXXX") when this number is logged in somewhere. If it's in Accounts, click Fetch code. If it's on your phone as a second account, check that Telegram app. Brand-new numbers need SMS for first login.

No SMS access? Scan the QR code with Telegram on your phone (Settings → Devices → Link Desktop Device). No code or SMS needed.

What is a session string? It’s a long line of text (starts with 1A... or 1B...) that represents a logged-in Telegram account. You get it by running a small script on your computer that reads your Telegram Desktop tdata folder and prints this string. You then paste that string here — no zip upload needed.

Step 1. On your computer (Mac/Windows), open a terminal in this project and run (use the real path to your tdata folder):

python scripts/convert_tdata.py "/path/to/your/tdata"

Examples: Mac ~/Library/Application Support/Telegram Desktop/tdata  |  Windows %APPDATA%\Telegram Desktop\tdata

Step 2. Copy the long line it prints (the session string) and paste it below, then click Import.

Or upload a zip: Only works if the zip contains the real tdata folder from Telegram Desktop (with map.json inside). Many “session” zips from other tools use a different structure and won’t work — use the paste method above instead.
